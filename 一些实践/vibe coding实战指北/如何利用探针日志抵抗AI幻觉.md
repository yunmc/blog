# 如何利用探针日志抵抗AI幻觉 (Runtime Probe Context)

在极其复杂的业务链路或高度抽象的重构区，仅靠静态代码的阅读极易引发 AI 的逻辑断层与幻觉（Hallucination）。必须将“运行时探针（Runtime Log）”作为一种最高保真度、最聚焦微观的动态上下文粒度，倒逼大模型基于系统级铁证进行收敛式排错。

### 1. 将“打补丁”转变为“架设监控” (Log Injection)
当介入难以复现的隐蔽 Bug 或深水重构区时，严禁提出“帮我修好它”这样极度发散的诉求。
*   **全节点快照指令**：明文规定：“在核心状态机流转的所有关键计算节点，必须立即铺展全覆盖的结构化日志（需包含入参快照、关键流转标识与执行耗时）”。要求系统转入白盒自证模式。

### 2. 运行时日志即最高等级上下文 (Log as Context)
当执行受阻时，切断一切 AI 单纯依靠报错信息发散盲猜的念头，由人工进行物理层介入勘验。
*   **人工取证与回喂**：由人类在端侧或服务器上触法流程，抓取带有确切流转参数的真实探针日志，提取后直接向大模型抛送这批最核心的 **运行时上下文 (Runtime Context)**。
*   **收敛级 Debug 断喝**：“这批是包含所有节点快照的真实运行日志流。基于该套系统级铁证，不再允许更改全局业务结构，只准给我精准定位发生截断或数据畸变的微观缝隙，并提交针对性修复。”

### 3. 完工后的无情清理 (Log GC)
探针日志是为了防范幻觉而搭建的临时施工脚手架。
*   **清扫防污染**：一旦模块核心跑通，绝对不允许高频的打印体残留在项目内污染生产级代码的整洁度。立刻下达强指令：“该核心链路已校验其真。立刻执行清场，剔除刚才所有为 Debug 铺设的临时 Console/Print 探针”。
