# 如何建立物理隔离防御：消除重构恐惧

在 AI 生成时代，普通代码已沦为廉价消耗品，项目的核心极密资产是“设计思路与设计模式”。必须彻底消除“AI 暴走毁坏原有可用逻辑”的心理恐惧，通过极端沙盒制实现零成本试错。

### 1. 物理层隔离：彻底绞杀代码污染 (Physical Isolation)
禁止在受保护的主分支 (Main/Master) 环境中直接驱动满血版 Agent 进行大刀阔斧的重构。
*   **沙盒化工作区 (Sandbox Workspace)**：在下放重构或试错指令前，强制切出平行工作区（Git Worktree）或构建专门的实验分支。使 AI 的一切生成与覆盖动作处于完全的物理隔离阀内，断绝主干污染。

### 2. 写前快照与低成本倒流 (Pre-write Checkpoint)
引入类似 Claude Code 的极致容错机制，将防御阵线推至行动发生前。
*   **强制回滚点 (Commit Anchor)**：在 AI 动刀前，强制建立当前可用状态的快照。
*   **禁止肉眼 Debug**：若大模型发疯将代码改得千疮百孔，严禁人为介入逐行排错（这将不可逆地打断 Vibe 心流）。第一动作是直接一键丢弃、强推回溯（Git Reset/Checkout）。通过“成本极低的无限次重来”对抗模型幻觉。

### 3. 剥离代码执念，榨取架构设计 (Design > Code)
*   **抛弃型重构 (Disposable Refactoring)**：确立“代码不值钱、随时可重写”的上帝视角。在沙盒分支中，利用 AI 的算力反复推翻重写同一模块，压榨出最优异的 [设计模式] 与 [高内聚结构]。待验证跑通后再合并 (Merge) 进主代码树。
