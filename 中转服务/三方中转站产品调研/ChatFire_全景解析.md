# ChatFire 全景解析

> 文档类型：平台全景解析
> 最近更新：2026-05-06
> 研究对象：https://api.chatfire.cn / https://chatfire.cn
> 核心判断：ChatFire 更像一个面向中文开发者的“大模型渠道池 + 统一 OpenAI 兼容网关 + NewAPI 风格运营中台”，而不是单一模型镜像站。

## 一、一句话定位

ChatFire 本质上是一个 **国内多模型 API 聚合网关**。

它和常见的 Claude 镜像 / OpenAI 代理相比，区别在于它不是只卖某一条海外通道，而是把：

- 海外主流模型
- 国内云厂商模型
- 图片 / 视频 / 语音 / OCR / 搜索等能力
- 按 token 与按次计费的多种 SKU

全部放进一个统一计费与控制台体系里。

## 二、公开站点呈现出的两个产品面

### 2.1 `api.chatfire.cn`：偏营销站与价格站

这个域名更像传统中转站的营销前台，公开信息包括：

- 强调按量付费、余额不过期
- 强调兼容 OpenAI 官方库及多数开源聊天应用
- 强调高并发、高稳定、透明计费、对公和发票
- 提供工作台、模型价格、接口文档、关于我们、聊天 / 绘画等入口

它的文案非常明显是面向中文开发者和中转站用户群：

- OpenAI API 国内替代
- Claude API 国内
- Claude Code 国内配置
- API 人民币充值
- Chatbox / NextChat / LangChain 配置

这说明它的主要获客逻辑，仍然是“帮助国内用户低门槛接入模型”。

### 2.2 `chatfire.cn`：偏现代控制台与模型市场

这个域名更像新一代控制台前台。首页直接写：

**The UnifiedLLM API Gateway**

并强调：

- Better price
- Better stability
- No subscription required
- Just replace the model base URL

它还直接列出了兼容的接口路径：

- `/v1/chat/completions`
- `/v1/responses`
- `/v1/messages`
- `/v1beta/models`
- `/v1/embeddings`
- `/v1/rerank`
- 图片与音频相关端点

这说明 ChatFire 的新前台，已经有明显的“统一模型网关”产品意识，而不只是卖 API 地址。

## 三、最重要的产品特征

### 3.1 OpenAI 兼容是它的核心入口

从首页和价格页信息看，ChatFire 最大的接入卖点是：

- 尽量沿用 OpenAI 心智
- 尽量减少用户代码改动
- 尽量覆盖聊天、向量、重排、图像、音频、多模态等接口

这一点和 OpenRouter 类似，但它更偏中文开发者场景，强调“国内替代”和“人民币支付”。

### 3.2 模型 / SKU 数量非常大

`api.chatfire.cn/pricing` 当前公开了 **855 个模型 / SKU**。

这不只是传统意义上的 LLM 模型，还包括：

- OpenAI / Anthropic / Gemini / DeepSeek / Moonshot / Qwen / xAI 等文本模型
- 图像生成与编辑
- 语音转文字、文字转语音
- 视频生成
- OCR / PDF / watermark remove / search / rerank 等工具型 API
- Midjourney、Kling、Sora、Veo、Jimeng、Seedream 等按次或按秒计费能力

这说明 ChatFire 的运营思路不是“少数精品模型网关”，而是明显偏：

**多渠道、多品类、大 SKU 的能力超市。**

### 3.3 渠道池运营痕迹很强

ChatFire 的价格页给出了很多普通中转站不会直接暴露的信息：

- Tier 1 / Tier 2 / Tier 3 / Tier 4
- 渠道分组
- 默认通道 / 企业通道 / 兜底专用通道
- AliBailian 0.6x / FlashSale 0.15x / Volcengine 0.5x / default 1x 等 token group 倍率
- 按 token、按次、按秒等混合计费模式

这意味着它背后很可能不是简单反代，而是一个 **渠道池运营系统**。

对我们来说，这类产品更值得借鉴的不是前台文案，而是：

- 多通道映射
- 多计费模型共存
- 大量 SKU 的运营面板能力

### 3.4 企业与 B 端信号明显

站点多次强调：

- 支持对公与发票
- 企业级 API 接入
- 模型定制化服务
- 个性化智能体
- 国内云厂商渠道
- 私有化部署

这表明它并不只面向个人开发者，也在试图承接：

- 企业采购
- 私有模型接入
- 混合云或本地部署
- 定制化 AI 方案

### 3.5 技术底座高度疑似开源聚合网关

这是 ChatFire 最值得记录的一点。

`chatfire.cn/about` 直接显示：

- New API project repository: `QuantumNous/new-api`
- Based on `One API v0.5.4`

这几乎等于公开告诉我们：

**它的现代控制台大概率是基于 NewAPI / OneAPI 体系做的商用化封装。**

这件事非常重要，因为它说明：

- ChatFire 不一定是从零自研所有网关能力
- 它的竞争力更可能在渠道供给、SKU 运营、价格体系、客户服务和商务能力
- 如果我们要研究“国内多模型聚合面板怎么快速起盘”，它是很直接的样本

## 四、价格与供给信号

从公开价格页看，ChatFire 采用的是典型的 **按量付费 + 部分按次 / 按秒计费**。

代表性价格示例包括：

- `gpt-4o`: Input ¥2.5 / M, Output ¥10 / M
- `gpt-5-mini`: Input ¥0.25 / M, Output ¥2 / M
- `claude-sonnet-4.5`: Input ¥3 / M, Output ¥15 / M
- `deepseek-chat`: Input ¥2 / M, Output ¥8 / M
- `qwen-turbo`: Input ¥0.1 / M, Output ¥0.2 / M
- 大量图像 / 视频能力按次计费，例如 `qwen-image`、`veo3`、`sora-2`、`mj_fast_imagine`

更重要的不是单个价格，而是它把：

- 官方模型
- 国内云模型
- 第三方供应商模型
- 自定义工具 API

混在同一个价格体系里统一售卖。

这说明它的商业逻辑比普通“海外 API 中转”更复杂，已经接近一个 **能力分销市场**。

## 五、它和 OpenRouter 的差异

| 维度 | ChatFire | OpenRouter |
|------|----------|------------|
| 主要市场 | 中文开发者 / 国内用户 | 全球开发者 / 企业 |
| 核心卖点 | OpenAI 兼容 + 人民币支付 + 大 SKU + 对公支持 | 路由控制 + 统一账单 + 隐私治理 + 企业能力 |
| 平台气质 | 强运营、强渠道、强 SKU | 强基础设施、强控制面、强治理 |
| 前台形态 | 营销站 + NewAPI 风格控制台并存 | 一体化产品官网 + 文档 + models/providers/rankings |
| 技术透明度 | 有运营痕迹，但底层能力公开较少 | 路由、隐私、provider policy 公开很多 |
| 适合借鉴的方向 | 多渠道 / 多 SKU 运营 | 路由 / 治理 / 企业化产品设计 |

一句话说，ChatFire 更像：

**国内版的大模型能力超市 + 渠道池运营平台。**

而 OpenRouter 更像：

**全球版的模型网关控制面。**

## 六、值得我们重点学的点

### 1. 大 SKU 组织方式

ChatFire 的价格页虽然不算优雅，但信息密度很高。它证明了一件事：

如果模型、工具、图像、视频、搜索都要卖，平台必须尽早准备：

- 分类体系
- 标签体系
- 渠道组体系
- 计费单位体系

### 2. 统一兼容入口

它很清楚地把接入门槛压到了“改 Base URL”这一级别，这对国内用户非常重要。

### 3. 对公和定制服务前置

很多中转站只敢做个人充值，但 ChatFire 明显在尝试企业采购、定制化模型和私有部署，这条路更接近长期生意。

### 4. 开源网关 + 商业运营封装

它说明一个现实：

很多时候，真正的护城河不在“网关代码是不是自己写的”，而在：

- 供给拿得到吗
- 渠道管得住吗
- 计费做得清吗
- 客服与商务跟得上吗

## 七、需要警惕的地方

### 1. 双域名、多前台并存

`api.chatfire.cn` 和 `chatfire.cn` 的产品形态差异比较大，这会带来：

- 品牌认知分裂
- 文档入口不统一
- 用户不确定到底该在哪个域名创建 Key 和使用控制台

### 2. 文档和 About 信息不够完整

虽然营销信息很多，但 `api.chatfire.cn/doc` 和 `api.chatfire.cn/about` 的有效内容偏少，`chatfire.cn/about` 甚至还是默认的 NewAPI About 页面。

这说明它在“产品化完成度”上，和 OpenRouter 这种平台还有明显差距。

### 3. 监控透明度存在疑问

首页宣称“提供公开日志”，但 `api.chatfire.cn/uptime` 当前返回 404。这个点如果属实，会影响“高稳定性”承诺的可信度。

### 4. SKU 太多会带来认知噪音

855 个公开 SKU 的好处是覆盖广，但坏处是：

- 用户很难快速找到该用哪个
- 价格一致性和质量一致性容易被质疑
- 内部运营复杂度会显著提高

## 八、对我们的启发

如果我们想做中转站，ChatFire 给我们的启发主要不是“抄它的页面”，而是抄这三件事：

1. **早做渠道池与分组能力**
   不要等到模型和渠道变多了，才临时补充运营结构。

2. **统一兼容入口优先**
   对外尽量让用户只改 Base URL、Key 和模型名。

3. **预留对公与定制化路径**
   只做个人充值，很容易陷入价格战；加上发票、企业通道、定制服务，产品空间会大很多。

同时，也要避免它的两个问题：

- 不要让多域名和多前台把用户搞乱
- 不要让大 SKU 先于信息架构成熟

## 九、一句话结论

ChatFire 不是单纯“某家模型的 API 中转”，而是一个 **中文市场导向、多渠道、多品类、大 SKU 的统一 API 网关与运营面板**。

如果 OpenRouter 更适合拿来学习“控制面和企业治理”，那 ChatFire 更适合拿来学习“国内多模型聚合站怎么做渠道池与商业化运营”。
